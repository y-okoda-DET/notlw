# 手順：作り直し（変わった所だけ作り直す）

`bash blender/build.sh <番号>` は毎回すべての段を通るが、時間のかかる焼き込みは、焼く直前の中身が前回と同じなら前の結果を使う。
どれを使い回したかは $WORK/build<番号>.log に出る（`cache hit` / `baked` / `LM_STALE`）。

## 何を使い回すか（判定は機械。下の表は人が読むためのもの）
| 段 | 使い回す条件（キー） | 置き場所 |
|---|---|---|
| 光の焼き込み（Cycles、夜・夕方それぞれ） | 焼く直前のシーンの中身のハッシュ：見えている全物体の形（ポーズをとった人物も含む）・UV・材質（ノードの値と画像の中身）・光・ワールド・Cycles の設定（blender/cache.py） | $WORK/cache/lm/ |
| VoxelGI の焼き込み（gi.res） | 家の glb・ライトマップ・lights.json・scene.json・project.godot・*.tscn・scripts/*.gd・shaders/* のハッシュ（build.sh） | $WORK/cache/gi/ |
| Godot の取り込み | Godot 自身が、元ファイルが変わったものだけ取り込み直す | godot/.godot/ |

人物の動きの記録（bake_action）は、記録の間だけ人物のメッシュの変形を止めて速くしている（結果の glb は同じ。NOTES.md）。

毎回作り直すもの：人物と家の glb（夜・夕方の書き出しそのもの）、ライトマップの網点ぼかし（denoise_lm.py）、人体の構造の確認、Windows 版、zip。

表で依存を管理しない理由：スクリプト同士が読み込み合っていて（export_dusk.py は export_godot.py・night.py を読む。chars.py は全員に効く）、表が1か所でも間違うと古い光が残る。中身のハッシュなら、表の間違いで古い結果が残ることはない。

## 元ファイルと、それが効く所（調べるときの目安）
| 元ファイル | 効く所 |
|---|---|
| tripo/prep_natsuki.py（雛形）・make_prep.py・chars_cfg.json | 全員の顔と首（prep を全員分走らせ直す。build.sh は prep を走らせない） |
| tripo/prep_<人物>.py・<人物>_body/head.glb・assets/faces_style/<人物>_*.png | その人物の顔（prep_<人物>.py を走らせ直す） |
| blender/chars.py | 全員（夜・夕方）。光の焼き込みも焼き直しになる（人物が光をさえぎるため） |
| blender/export_godot.py の pose_* | その人物の夜のポーズ。夜の光の焼き直し。夕方は export_dusk.py が読み込むので書き出しは走るが、夕方の光は変わらなければ使い回し |
| blender/export_dusk.py の pose_* | その人物の夕方のポーズ。夕方の光の焼き直し |
| blender/hall.py・door.py・lib.py・shot.py・night.py | 家と光（両方の場面）。光と VoxelGI の焼き直し |
| godot/scripts・shaders | 見え方。VoxelGI の焼き直し（光の焼き込みは変わらない） |

prep の結果（tripo/*_prep.blend、*_headtex_*.png）はリポジトリに入っていて、build.sh は prep を走らせない。
ただし *_head_bakenrm.png・*_head_bakecol.png は入っていない（.gitignore）。新しい作業環境では prep を全員分走らせてから書き出す（SETUP.md 6）。走らせないと、頭の法線の画像がないまま書き出される（ログに `Image file ... bakenrm.png does not exist`）。

## 速い書き出し（直している途中）
`FAST=1 bash blender/build.sh <番号>`
- 光の焼き込みが使い回せないとき、同じ形の家（同じ UV）で焼いた最新の光を使い、ログに `LM_STALE` と出す。人物や光の強さを変えた直後でも焼き込みを待たない。
- zip は作らない。pck（$BUILD/RULES_proto<番号>/RULES.pck）だけ。
- `FAST=1 SCENES=night`（または dusk）で、直した場面だけを書き出す。もう片方は前回の書き出しのまま。export_godot.py の pose_* のように片方の場面だけに効く直しで使う。chars.py・prep のように両方に効く直しでは使わない。
- 家の形を変えたときは、FAST でも焼き込みになる（古い光は UV が合わないので使えない）。
- ユーザーが OK を出したら、FAST なしで作り直す。そのときは中身が違う所だけ焼き直す。

## 以前の SKIP_LM / ENV
`SKIP_LM=1 python3 export_godot.py` は今も動く（ディスクにあるライトマップをそのまま使う。env.glb も書き出さない）。
build.sh からは使わない。FAST=1 のほうが、家の形が変わったときに自動で焼き直すので安全。

## キャッシュを消すとき
`rm -rf $WORK/cache`（次の書き出しはすべて焼き直す。中身の判定を疑うときに）。
