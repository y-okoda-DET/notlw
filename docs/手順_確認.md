# 手順：確認

確認のルールはこのファイルだけに書く（プロジェクトの指示・決定事項には書かない）。機械で調べられるものは `blender/check.sh` に入れ、覚えておく量を減らす。

## 1本で回す（送る前に毎回）
1. 書き出す（確認用は光の焼き込みを省いた速い書き出しでよい）。
2. `bash blender/check.sh <確認する pck> <直す前の pck> <指摘の一覧>` を run_in_background で走らせる（約1時間。最後が `CHECK_DONE`）。
3. `/home/claude/work/check/一覧.md` の各行に ○／× を書く。× が残っていたら直して 1 に戻る。
4. 独立レビュー（下の「送る前」）。
5. ユーザーに送る画は check/ の中から選ぶ（刷りあり。形を見せるときは刷りなし・確認用の光の画も添える）。

### 指摘の一覧の書き方（/home/claude/work/check_items.txt など）
1行に1つ。`ユーザーの言葉そのまま | 場面 bx,by,bz 距離 方位,方位 時刻,時刻 [高さ]`。ゲームの中で撮れない位置（扉の外の夏希など。カメラはプレイヤーなので壁に押される）は `| v4` と書き、4方向の画で見る。方位はカメラが壁の外に出ない側を選ぶ（夜の大河なら玄関側から。扉の外からは撮れない）。言葉は言い換えない。位置はユーザーのスクリーンショットの名前、または指摘された画と同じにする。
```
大河の腕は両腕とも肘から先が外側に旋回している | night .5,5.85,1.25 .9 330,0,20 2.0,8.0
```

## 原則
- ユーザーに見せる画は、書き出した pck から撮る（close.py、`PCK=… PRINT=1`）。Blender の画は途中経過と 4方向（人物だけ）に使う。
- 網点ありの普段の見え方で見る。おかしく見えたら、網点なし＋確認用の光で同じ位置を撮り、形の崩れか見え方かを分ける。
- 全員に効く処理（tripo/prep_natsuki.py と make_prep.py、blender/chars.py）を変えたら、全員を作り直す（check.sh は全員を撮る）。段階0では、ある人物のための処理が別の人物の襟とあごを壊した。
- ユーザーのスクリーンショットは、名前に場面・位置・向き・時刻が入っている。その位置を指摘の一覧に書く。
- 自分が直したところを、直ったと見える角度で撮らない。人間が見る角度で撮る。
- 前提（どちらが手のひらか、など）を疑う。数値が合格でも、画が人間に見えなければ不合格。
- 確認していないことは「確認していない」と書く。

## 速い回し方（1回 10〜15分）
- 人物だけ直したとき：`SKIP_LM=1 python3 export_godot.py`（光の焼き込みと env.glb を飛ばす）→ Godot の取り込み → 確認画。
- 確認画は書き出しを待たずにプロジェクトから撮れる：
  `close.py <scene> <名前> <bx,by,bz> <距離> <方位,...> <時刻,...> [高さ] [確認用の光]`
  1コマ約20秒（`--at=` でその時刻から始め、12コマで終わる）。
- 暗い場面の手元は確認用の光 0.12〜0.25（刷りの明るさは 1.0 になる）。本番の光ではないことを明記する。
- Windows 版は、ユーザーが静止画で OK を出してから作る。

## 必ず撮る角度
| 項目 | 角度 | 不合格の例 |
|---|---|---|
| 顔 | 正面・見上げ・真横・後ろから回り込み | 段差、裂け目、色の違い |
| 首 | 真横・斜め後ろ（反応の前・最中・後） | 襟の上に首が乗る、ねじれ |
| 手と持ち物 | 手のひら側・甲側・本人の目 | 甲に乗る、指が物を貫通、指が画面にかかる |
| 手と面（扉・板） | 横・上 | 指が面を抜ける |

## 4方向（人物だけ）
- `bash blender/view4_glb.sh`：書き出した glb を Blender で開き、人物ごとに正面・横・後ろ・横を撮る（/home/claude/work/v4/）。ゲームの中は廊下が狭く、カメラ（プレイヤー）が壁に押されて撮れない向きがあるため。刷りの見え方はゲームの中の画で見る。

## 動きの確認（試作18から必ず行う）
- 静止画1枚では、反応の途中で首がねじれる・袖が開く・指が物を抜ける、といった崩れが見えない。同じ位置から時刻だけを変えて6回撮り、並べて見る。
- `python3 godot/motion.py night` と `python3 godot/motion.py dusk`（人物を絞るときは `night taiga,kiryu`）。1人約4分、夜3人・夕方4人で約30分。run_in_background で走らせ、最後が `MOTION_DONE` かを見る。
- 1人につき2枚：首と襟（顔の向きから120°回った斜め後ろ）、腕と手（顔の向きから35°の斜め前）。各6時刻。
  - 夜：2.0（前）・6.3（1回目のノックの最中）・8.5（桐生が見る）・11.3（2回目のノック）・14.0・19.0（後）
  - 夕方：1.0（前）・3.6（真琴が桐生を見る）・6.8（桐生が見上げる）・9.0（間）・12.5（大河が振り向く・真琴がもう一度見る）・16.0（後）
- 形を見るための画なので、刷りなし・確認用の光あり（夜 0.2、夕方 0.12）。刷りの見え方は通常の確認画で別に見る。
- 見るもの：首（襟から首が浮く・ねじれる・あごが襟に刺さる）、腕（袖口が開く・裂ける、ひじの折れ）、手（指が物や面を抜ける、手首の折れ）。6枚の中で1枚でも崩れていれば不合格。
- 人物の位置と向き・時刻は motion.py の表にある。場面の配置や反応の時刻を変えたら表も直す。

## 人体の構造の確認（試作18から、確認画を送る前に必ず行う）
試作18で、夏希（夜）の体が頭と逆向き、大河の前腕が前腕ごとねじれている、の2つを「直った」と送ってしまった。どちらも人体の構造と照らし合わせれば防げた。見た目の印象ではなく、次の項目を1つずつ確かめる。

**自動の確認**：`python3 blender/anatomy.py`（全員の glb。最後が `ANATOMY_OK` か `ANATOMY_NG 件数`）。顔（*_face の材質）とつま先が骨の正面と同じ向きか、ひじ・ひざが逆に曲がっていないか、前腕の骨そのものの回り（45°まで）とひねりの骨の回り（110°まで）を見る。build.sh に入っていて、NG なら止まる。自前の確認スクリプトにも必ず入れる。

**向き（ポーズなしと、ポーズありの両方で）**
- 顔・胸・つま先・ひざ・ジーンズの前（ファスナー側）が、すべて同じ向きか。顔が見える側を正面と決めつけない。
- 持ち物の向き：スマホの画面は持つ本人を向く。

**関節（曲がる向きと範囲）**
- ひじ・ひざは一方向にしか曲がらない。逆に曲がっていないか。
- 前腕のひねり（手のひらの向きを変える動き）は、ひじ側はほとんど回らず、手首側に向かって増える。前腕全体が棒のように回っていないか（ひじのしわ・袖ごと回っていないか）。範囲はおよそ ±90°。
- 肩・首・手首が、人が実際にできる角度を超えていないか。

**比べ方**
- ユーザーの指摘は、そのままの言葉で確認項目にする。言い換えない。
- 直す前と後を、同じ角度・同じ時刻で並べる。その項目が変わったかを見てから「直った」と書く。
- 参考写真がある場合は、写真と同じ角度で撮って並べる。
- 独立レビューにも、ユーザーの指摘をそのままの言葉と、この項目一覧を渡す。

## 送る前（独立レビュー）
- 何を直したかを知らない別のエージェントに、画像・参考写真・ユーザーの指摘の言葉（そのまま）・「人体の構造の確認」の一覧を渡し、「人の体として不自然なところ」「写真との違い」を挙げてもらう。
- 結果は、問題と判断したもの・しないもの、それぞれの理由を添えてユーザーに伝える。見ていないものは「未確認」。
