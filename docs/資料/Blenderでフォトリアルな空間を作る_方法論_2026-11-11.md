# Blender でフォトリアルな空間を作る：方法論

（2026-11-15 ユーザーから受け取った。ユーザー「部屋の作り方、これを参考にしてほしい」。インタビューの部屋を Blender で建てるときの手引き。原文のまま）

Nov 11, 2026 · @おおこだ

## このドキュメントについて

瀬戸内の港町を Blender（Cycles）でフォトリアルに作った約50回の繰り返し（lk01〜lp03）と、前の九龍城のプロジェクトから学んだ進め方をまとめたものです。次に別の場面を作るときに、最初に読む手引きとして使います。

| 項目 | 中身 |
| --- | --- |
| 目標 | お手本の写真2枚（＝100点）に並ぶ2カット。雨上がりの黄昏、雁木と常夜灯、坂の路地 |
| 道具 | bpy 5.2（Python のモジュール）、Cycles CPU、AgX、OIDN のノイズ除去。手作業のモデリングはしない |
| 到達点 | 本番の描画（1500px・128 サンプル）で、独立の採点がカット1 62点、カット2 60点 |
| 回した数 | 箱組み 3回、質感と形 36回、改善のループ 3周、本番 1回 |

点の数字は採点の担当ごとに 10〜20 点ずれるので、絶対値ではなく、同じ担当が並べて付けた差で読んでください（評価のしかたの節）。

## 一番大事な結論

点を大きく動かしたのは、構図と大きな形だけでした。時間の大半を使った材質の調整は、1回 ±1 点で、採点の誤差の中でした。

| 変えたもの | 例 | 点の動き（同じ担当の差） |
| --- | --- | --- |
| 構図 | カット1を「段の上から見下ろす」→「常夜灯を右に大きく」 | 構図だけで 62→76、全体で +10〜16 |
| 大きな形 | 石段を横長の石に、漁船を横向きに | 各 +2〜3 |
| 明暗の設計 | 火袋・空・海の明るさの目標を満たす | 少し（満たさないと大きく下がる） |
| 材質の調整 | 濡れ、汚れ、色、粗さ、焼杉の割れ目 | ±1、後退も数回 |
| 式で作った遠景 | 島の稜線の刻みを 2 倍、霞 4 層 | ±1（3 周で変わらず） |

だから、効く順に手を付けます。構図 → 大きな形と輪郭 → 空と光 → 主役の作り込み → 材質。材質は最後にまとめて調えるもので、点が止まったときに戻る場所ではありません。

もう一つは、「式で作れない物は写真に頼る」ことです。数百 m 先の山や空は、式の起伏をどう増やしても「なめらかな円錐」「縞の雲」に見えました。こういう所は、早めに HDRI（空の全周写真）や写真素材に替える判断をします。

## 進め方の順番

九龍城で効いた順番は、今回も正しかったです。ただし「構図を決めたら動かさない」と扱ったのは間違いで、約30 回も細部を直してから、ようやくカメラを変えました。

1. **画面の設計を先に決める**：カット、時間と天気、主役、手前・中・奥の3層、明暗の山。お手本の写真と並べて決め、明るさの目標を数値で書く
2. **箱で組んで構図を確かめる**：カメラの候補を 4〜8 枚、低いサンプルで描いて比べる。構図だけの独立レビューを入れる
3. **形を作り込む**：箱を崩す（面取り、傾き、付属物、同じ部品を並べない）。主役は寄りのカメラで作る
4. **質感**：理由から決める（濡れ → 汚れ・錆 → 色ムラ）。写真は素材そのものだけ
5. **照明**：主役の光、色温度の違い、白飛びさせない
6. **空気と仕上げ**：霞・空気遠近法、後処理

この順番に、今回の学びを 2 つ足します。

- **踊り場に来たら、まず構図を疑う**：細部を足す前に、カメラの候補を描き直して比べる。今回はこれで +10〜16 点動きました
- **式で作れない物を、設計の段階で洗い出す**：空、遠い山、風化した石など。写真素材（HDRI、テクスチャ）を最初に揃える

## 構図とカメラ

構図は、一番少ない手間で一番点が動く所です。候補を何枚も描き、構図だけを別担当に比べてもらいます。

- **主役は大きく**：常夜灯が画面の高さの 4 割で右端に小さい構図は「主役が弱い」。約 7 割にして、明るい海を背にしたら構図の点が 62→76
- **手前の床は 2〜3 割まで**：床が画面の 4 割を占めると「何もない面」として毎回減点された
- **手前・中・奥の 3 層に、それぞれ読める物を置く**：中の層が空だと「中が空っぽ」。横向きの漁船・係船柱と綱で埋まった
- **物の向きも構図のうち**：船を岸に平行に置くと、カメラから船の端しか見えない。船首を岸へ向ける（縦付け）だけで +3
- **暗い枠を置ける場所も一緒に確かめる**：お手本の左手前の暗い家を、新しいカメラでは置ける場所がなかった

**見下ろしの罠**

- 段の蹴上げは、上から見下ろすと向こうを向いて写らない。段に読ませるのは、踏み面の鼻の線と、その影の帯
- 段の勾配が視線より急だと、踏み面がまったく写らない。水へ下りる雁木（蹴上げ 0.3m・踏み面 0.5m）は、高さ 7m・距離 20m のカメラから消えた。置く前に、視線の角度と段の勾配を比べる
- 細かい段（0.15m / 0.55m）は、見下ろすと床に見えた。大きな段（0.3m / 1.1m）なら段に読めた

**カメラの置き方**

- 配置の基準と撮影用のカメラは別のファイル（layout.json と cameras.json）に書く。カメラを動かしても配置がずれない
- 候補は \_alts に残し、採用した日と理由を note に書く
- 向き（yaw）の試しは「どちらへ振ると主役がどこへ動くか」を先に計算する。一度、逆に振って 4 枚とも主役が画面外に出た
- 画面の端に物の角だけが入ると「宙に浮いた破片」に見える。光線を飛ばして何かを特定し、レンズを少し締めて外す

## 明暗と色

明暗は、目で見て決めずに数値の目標を書き、描くたびに自動で判定します。目標を満たしたあとは点が大きくは動きませんが、外れていると大きく下がります。火袋が目標に届いていないことを、数値は出ていたのに 10 回ほど見落としました。

| 測る所（仕上げ後、輝度 0〜255） | 目標 | 理由 |
| --- | --- | --- |
| 主役の灯り（火袋・外灯） | 235 以上、空の 1.4 倍 | 暗いと主役が浮かない。172 で「光っていない」と言われた |
| 空 | 150〜170（路地は 160〜190） | 灯りとの差を残す |
| 主役の後ろの海 | 主役の石 +25 以上 | 石を影絵として立たせる |
| 白壁（漆喰） | 100 以上 | 暗いと「灰色の板」に見えた |
| 潰れ（輝度 10 未満） | 画面の 3% 以下 | 日陰の壁が黒い塗りになる |

**測り方で間違えやすい所**

- 材質ごとの割合と明るさは、カメラから画素ごとに光線を飛ばして、どの物が写るかで測る（霞の箱は隠す）
- 灯りは「暖色の画素全体の上位 %」ではなく、ノイズを除いた暖色の最大で測る。前者は壁の照り返しを測っていた
- 材質の平均と見た目はずれる。常夜灯の石は平均 49 で目標内でも、胴だけを見ると 29 で暗すぎた

**色と光の作り方**

- AgX は、明るい発光体を白へ寄せる。灯りの発光体は深い橙で強さを控え、周りは別のライトで照らす
- 火袋の中の点光源は、発光体の影に閉じ込められる。発光体の影を切る（visible\_shadow=False）
- 点の灯りは、濡れた石に丸い白い鏡の点を作る。灯りの specular\_factor を下げる
- 暗部の潰れには、頭上の空の青い回り込みを広い面の光で足す（カット2 で 5.8% → 3.8%）。強すぎると床が明るくなりすぎる
- 仕上げで全体を寒色に寄せたら、白壁が 101→73 に沈んで後退した。色の変更は、白の目標と一緒に確かめる
- 黄昏で「西の低い空は橙、上は青灰」の色温度の差は、式の空では最後まで出せなかった。HDRI の候補

## 形

「新品のきれいな箱」に見えるのが、CG と分かる一番の目印です。形は材質より効きますが、大きすぎる崩しは「溶けた粘土」に見えます。

**石段（一番学んだ所）**

- 幅 0.3〜0.65m の石は奥行きと同じくらいの四角になり、タイルの格子に見えた
- 段の幅の方向に長い石（0.7〜2.4m）にし、前の列を段の縁の長い角石に揃えたら、段に読めた（+3）
- 石 1 枚ごとに、上面を細かい格子にして形で作る：縁の丸め、小さく鋭い欠け、中のすり減り、小さな傾きと沈み、輪郭のわずかな揺れ
- 縁の丸め 2〜3.5cm と輪郭の揺れ 3〜8mm は「座布団」。丸めは 3〜25mm の範囲で、担当によって好みが割れた
- 石の形は、担当どうしで「長く」と「30〜60cm に」の逆の指摘が出た。お手本の写真を物差しにする

**屋根と軒先**

- 屋根は板 1 枚ではなく、棟と軒を 3〜9cm たわませ、軒先を波打たせる
- 近くの屋根だけ、桑瓦の波と段を形で作る（カメラから 120m 以内）
- 瓦の面が板の端で終わると、厚い板の直線が軒の輪郭になる。軒丸瓦と瓦当を並べる
- ただし軒先の瓦が「櫉の歯」のように揃うと、それも CG の目印になる。1 枚ごとに角度と色をずらす

**細い形と格子の解像度**

- 細い形は、格子の間隔の 3 倍以上の幅にする。常夜灯の笠の隅棟を 24×24 の格子に足したら、稜線がギザギザになり −3（72×72 で直った）
- 主役の輪郭が空を背にしている所は、一番目につく。形の不具合がそこに出ると大きく減点

**使い込まれた気配は形で**

- 漁船：古タイヤの防舷材、トロ箱、網の山、舷い綱。ただし「同じタイヤが等間隔」はそれ自体が CG の目印になる
- 家並み：同じ家の繰り返しはすぐ見抜かれる。軒の高さ、出、古さ、2 階建ての混在、向きの振れ

**遠景の限界**

- 島や山を式（峰の重ね合わせ・尾根と谷の刻み・木の塗宣）で作ったが、どれだけ起伏を増やしても「なめらかな円錐の重なり」と言われ続けた
- 木の塗宣（小さな球を 8000 個）は、近い山には少し効いたが、数百 m より先では画素に溶けて意味がない
- この距離は写真の領分。早めに HDRI や写真の背景に替える

## 質感

質感は「なぜそこがそうなるか」を先に決めてから式にします。ただし点への効きは小さく、最後にまとめて調える所です。

**理由から決める順番**

1. 濡れ：乾いた所／濡れた所／水たまりの 3 段。軒の下は乾く（AO で判定）、低い所に溜まる
2. 汚れと錆：雨だれは張り出しの真下から、水際ほど傷む、棟ごとに古さを変える
3. 色ムラ：同じ部品でも 1 枚ごとに明るさ・色合い・粗さをずらす（面の属性 stone\_rnd など）

**写真テクスチャの使い方**

- **色は写真、凹凸は形**：石垣に写真を貼ったら、式で作っていた石の凹凸が消えて平らな絵になり、後退した。写真の高さ情報で面を押し出すと（近くだけ細かく分割して置き換え）、石に影が出た
- **貼る向きを壁に合わせる**：箱投影では、y 方向を向く壁で板の写真が 90° 回った。壁に沿った座標（横 = x+y、縦 = z）で貼る
- **大きさを実寸で**：石の写真が大きすぎると「床のタイル」。石 1 個が本物の大きさになるように合わせる
- **当てる物を選ぶ**：磨いた赤い家具の木の写真は、古い板壁には使えない。写真は「素材そのもの」だけ
- **差し替えたら必ず確かめる**：置き換えの表に文字列が合わず、焼杉の差し替えが黙って無効になった。置換は assert で当たったことを確かめる

**素材ごとの学び**

| 素材 | 効いたこと | 後退したこと |
| --- | --- | --- |
| 踏み石 | 濡れを戦す（粗さ 0.14〜0.3）、水たまりに空が映る | 半乾き（0.3〜0.45）は「乾いて見える」、面全体が光ると「陶器のクッション」 |
| 焼杉 | 黒い板、写真の木目 | 細かい割れ目のノイズは「紙やすり・モルタル」 |
| 漆喰 | 写真の漆喰、明るさ 100 以上 | AO の汚れを強くすると灰色の板に沈む |
| なまこ壁 | 目地を白く盛る | 灰色の上に灰色で格子が読めない |
| 瓦 | 形の波と段、粗さ 0.42 | 粗さ 0.3 と強い凹凸は「空を映した青いトタン」 |
| 海 | 粗さ 0.035 と細波の凹凸 | 完全な鏡、乳白の平らな板 |

## 空気と遠景

霞は式でうまく作れましたが、空と遠い山は式では最後まで本物に見えませんでした。

**霞（作れたもの）**

- 世界全体の体積ではなく、範囲を限った霞の箱を置く。箱が高すぎると空が灰色になり、濃すぎると水平線が灰色になる。高さ 115m、密度 0.0003 で落ち着いた
- ライトは霞の散乱に効かせない（visible\_volume\_scatter=False）。灯りの周りが白く曇る
- 遠い物の材質に、距離と高さで空の色へ寄せる式を組み込む（奥ほど、高い所ほど霞む）。層ごとに霞の濃さを変えて 3〜4 層に分ける
- 西の島ほど夕空の色を受けるように、霞の色を方角で変える

**空（作れなかったもの）**

- 式の空（色の帯、太陽の光のグロー、雲のノイズ）は、最後まで「等間隔の平行な縞の雲」「灰紫の一色」と言われた
- 空は画面の 15〜20% を占め、光の色も決める。HDRI（空の全周写真）に替えると、雲と色温度の差と光が一度に本物になる見込み（未検証）

**遠い山（作れなかったもの）**

- 高さの場の峰を重ね、尾根と谷の刻み、木の模様、霞 4 層と重ねても、「同じ形のなめらかな山の重なり」のまま
- 数百 m より先は、遠景の写真（水平線に島が写った HDRI、または背景の板に貼った写真）に替えるのが近道

## 評価のしかた

信用できたのは、同じ担当に番号を伏せて並べてもらった「差」だけでした。絶対値は担当ごとに 10〜20 点ずれ、差も ±2 点は誤差です。

**採点の決まり**

- 自分では採点しない。作った側の説明を渡さず、画像だけで別担当にお手本と比べてもらう
- 新しい版だけではなく、基準の版を 2〜3 枚混ぜて、記号を振って順番を伏せる。各回の点は「新しい版 − 基準の版」で読む（担当ごとの物差しの違いが消える）
- 基準の版は、新しい版と同じサンプル数・解像度で描いたものにする。本番の画（128 サンプル）を基準にしたら、ノイズの分だけ 64 サンプルの版が 1〜2 点不利になった
- 数回に一度、過去の版をまとめて 1 人に採点してもらう（ベンチ）。回ごとの差は膨らみやすく、通して見ると 7 回で +3 だったこともある

**レビューの読み方**

- 「直せば +6〜8」などの見込みは当たらなかった。実際は +1〜3。順番は、見込みの数字ではなくてこの大きさ（構図 → 形 → 光 → 材質）で決める
- 細かい指摘は、担当どうしで逆のことを言う。二人以上が同じことを言うまで「未確認」として置く
- 何人もが毎回挙げる指摘は、直すまで消さない一覧に残す。浮いた軒の破片を 6 人が指摘していたのに、取りこぼした
- 「一目で CG と分かる所」を毎回聞く。その一位が、次に直す所の一番の候補

**数値の検品（採点の前に）**

- 組み立てるたびに、めり込みと宙に浮いた物を数えて 0 を確かめる
- 明るさの目標を自動で判定し、外れた項目が前より増えたら、採点に出さずに直す

## 改善のループ

1 周で変えるのは 1 つの仮説にまとまる範囲だけにし、判定を数字で決めておきます。そうすると、何が効いたかが分かり、踊り場も早く気づけます。

選ぶのは、未解決の指摘の一覧の上から 2〜4 件です。てこの大きい順（構図 → 大きな形 → 空と光 → 主役 → 材質）に取り、材質だけの周は作りません。人間と合意した構図を変えるとき、素材が要るとき、5 周ごとにも止まって報告します。

今回は lp01〜lp03 の 3 周がどれも「変わらない」で、式で作った遠景と空の限界に早く気づけました。それ以前は、同じ状態で 30 回近く細部を直していました。

## スクリプトとツールの作法

形・配置・質感・照明はすべて Python のスクリプトで作り、手作業のモデリングはしません。同じ入力から同じ場面が組み上がるので、戻すのも比べるのも簡単です。

| ファイル | 役割 |
| --- | --- |
| data/layout.json | 配置の基準（岸壁、石段、家並み、船、島）。変えた理由を \_note に書く |
| data/cameras.json | 撮影用のカメラ。候補は \_alts に残す |
| build\_blockout.py | 場面を組み立てて .blend に保存 |
| lookdev\_preview.py | 材質を差し替えて描く（組み立てと分ける） |
| render\_cams.py | カメラごとに描き、材質ごとの割合と明るさを測る |
| selfcheck.py | めり込み、宙に浮いた物、持ち主から離れた部品、船の喫水 |
| check\_targets.py | 明るさの目標の OK / FAIL |
| round.sh | 1 回分（組み立て → 検品 → 2 カット → 仕上げ → 判定）をまとめて回す |
| bench.py | 基準の版と混ぜて記号を振る（鍵は別ファイル） |

**乱数**

- 機能ごとに乱数を分ける（`random.Random(f"{seed}:<機能名>")`）。1 つの値を変えて全体が組み替わる事故を防ぐ
- 乱数を使う数が変わる変更はしない。隙間の範囲を変えたら、家が全部組み替わった。家を減らすときは「作ってから消す」
- 新しいばらつき（向きの振れ、灯りの間引き）は、別の名前の乱数で足す

**書き方の罠**

- 文字列の置換でスクリプトを直すときは、当たったことを assert で確かめる。範囲の置換で別の定義を消したこともある
- 関数の中で、別の関数と同じ名前の変数を作らない（`cyl` で UnboundLocalError）。一時の名前は \_ で終える
- 位置の足し忘れで、部品が原点に作られて空に浮いた。持ち主から 5m 以上離れた部品を検品で拾う
- 同じ高さの面が重なると黒くちらつく。1cm ずらす

**描画の運用**

- 確認はサンプル 12〜64・幅 400〜900px、本番は 128・1500px（1 カット約 1 時間）
- 主役は寄りの確認カメラ（zz\_ で始まる名前）で作り、全景へ戻す
- 画の中の「何か」を特定するときは、カメラからその画素へ光線を飛ばして物の名前を得る
- 作業場所は再起動で消えることがある。区切りごとにまとめの zip を作る

## よくある失敗

一度踏んだ失敗を、見え方から引けるように並べます。詳しい経緯はプロジェクトの docs/lessons.md に 1 行ずつあります。

| 見え方 | 原因 | 対策 |
| --- | --- | --- |
| 石段が床に見える、写らない | 見下ろしでは蹴上げが向こう向き。段の勾配が視線より急 | 大きな段。鼻の線と影で読ませる。置く前に角度を比べる |
| 床がタイルの格子 | 石が奥行きと同じ大きさの四角 | 段の幅方向に長い石、目地をずらす |
| 石が座布団・粘土 | 縁の丸めと輪郭の揺れが大きすぎる | 丸めは数 mm〜2cm、欠けは小さく鋭く |
| 灯りが白い箱に飛ぶ | AgX が明るい発光体を白へ寄せる | 発光は深い橙で控えめ、照らすのは別のライト |
| 灯りが周りを照らさない | 点光源が発光体の影に閉じ込められた | 発光体の visible\_shadow=False |
| 濡れた石に丸い白い点 | 点の灯りの鏡面反射 | 灯りの specular\_factor を下げる |
| 空や水平線が灰色 | 霞の箱が高すぎる・濃すぎる | 箱の高さと密度を下げる |
| 白壁が灰色に沈む | 寒色の仕上げと強い汚れを同時に入れた | 白の目標（100 以上）を毎回確かめる |
| 石垣が平らな絵 | 写真が形の凹凸を置き換えた | 写真は色、凹凸は形か置き換え |
| 板が縦に回る | 箱投影で壁の向きによって回転 | 壁に沿った座標で貼る |
| 稜線がギザギザ | 細い形に格子が粗い | 格子の間隔の 3 倍以上の幅 |
| 宙に浮いた破片 | 画面の端に物の角だけが入る／位置の足し忘れ | 光線で特定、レンズで外す／迷子の検品 |
| 船が白い箱 | 船をカメラに対して端向きに置いた | 横腹をカメラへ向ける |
| 家が全部組み替わる | 乱数を使う数が変わった | 乱数を機能ごとに分ける、作ってから消す |
| 点が動かないのに細部を足し続ける | 構図を「決まったもの」と扱った | 踊り場ではまず構図の候補を描く |
| 採点が特定の版をひいきする | 基準の版だけサンプル数が多くノイズが少ない | 同じ条件で描いた版を基準にする |

## 次のプロジェクトで最初にやること

始めの 1 日で、構図・明るさの目標・写真素材・採点の仕組みまでを揃えます。今回はこれを後回しにして、細部の調整に時間を使いました。

- [ ] お手本の写真を ref/ に置き、カット、時間と天気、主役を人間と決める
- [ ] 明るさの目標（主役、空、背景、白、潰れ）を数値で書き、自動の判定を先に作る
- [ ] 「式では作れない物」を洗い出し、素材を揃える：黄昏などの HDRI、遠景の写真、風化した石や木のテクスチャ
- [ ] 箱で組み、カメラの候補を 6〜8 枚描いて、構図だけを独立レビューに出す（主役の大きさ、手前の床の割合、3 層、暗い枠を置ける場所）
- [ ] 基準の版を決め、伏せた採点の道具（bench.py、頭み方の文面）を用意する
- [ ] 未解決の指摘の一覧を作り、てこの大きさ（構図・形・光・主役・材質）で並べる
- [ ] 改善のループを回す。2 周続けて「変わらない」なら、細部を止めて構図か素材の入れ方を変える
- [ ] 区切りごとにまとめの zip を作り、学んだことを lessons.md に 1 行ずつ書く
