- 人物ごとに一定の個性（語尾・呼び方・文の長さを固定）。映画の固有名詞（作品名・監督・役名・用語）をほぼ全ての会話に入れる。作品名は『』。台詞を書く・直すときは毎回この文書に照らす。

**感想の進め方（決定事項 2026-11-14）**
- ユーザーの指摘はざっくり届く。E のスレッドが E／H の線（決定事項 2026-11-14 朝）で仕分けし、聞かずに直す。H に回した物は docs/仕上げに回す物.md に積む（ステップ H はこの一覧から始める）。

**確認（docs/手順_確認.md だけに書いてある）**
- 送る前に毎回、全項目の `bash blender/check.sh` を回し、$WORK/check/一覧.md がすべて ○ になってから送る。速い確認（FAST=1）の一覧では送らない。
- 「直った」と書けるのは、ユーザーの指摘をそのままの言葉で項目にし、直す前と後を同じ角度で並べて変わったと確かめたときだけ。確かめていないことは「確かめていない」と書く。
- 全員に効く処理（prep の雛形・make_prep.py・chars.py）を変えたら全員を作り直して見る。
- 変えた物に合った確認をする（手順_確認.md「何を変えたら、何を確かめるか」）。check.sh の一覧は人物の形の確認で、流れ・刷り・重さは別に確かめる。遊びの流れを変えたら通しを回す。

**記憶（docs/プロジェクトの指示.md 6）**
- Claude のメモリは使わない。残るのはリポジトリの資料だけ。ユーザーが決めたことはその回のうちに決定事項.md に、区切り（画や版を送った、方針が決まった、長い処理の前、スレッドを終える前）ごとにこのファイルの上の3節を上書きして、main に push する。
- このファイルだけを読んだ新しいスレッドが、いまの段階・次にやること・誰が何をやっているか・ユーザーの返事を待っていることを、聞き直さずに言えるように書く。

**進め方（docs/決定事項.md）**
- 確認画（書き出した pck から、網点あり）でユーザーが OK を出してから、光を焼き直した配布用を作る（FAST なしの build.sh）。
- 指摘はまとめて受けてまとめて直し、1回の書き出しで出す。終わる時刻の見込みを伝え、ずれたら理由と新しい見込みを伝える。
- 持ち方・押し方の正解はユーザーの参考写真（docs/参考写真/）。言葉の条件を並べて組まない。
- 頭と体は Tripo で別々に作ってつなぐ。描いた顔は頭の質感に焼き込む。画像生成は ChatGPT、プロンプトは1つずつ分けて貼れる形で。
- ユーザーからの画面録画は不要（F12 の画像名から同じ画を再現する）。Blender・Godot をユーザーの PC に入れる作業は、劇的に速くなる場合だけ相談。
- Windows 版を作るのは、ユーザーの OK のあとで、区切り（章の流れができた、舞台ができた）か歩き・操作が変わったときだけ。zip が 400MiB を超えそうなら pck を本体と家の2つに分ける。
- ゲームに入る変更の main への入口は1本（上の「スレッドの分担」）。書き出しは、入口の PR が入った main から1回だけ。マージの前に「入った物／まだの物」の一覧をユーザーに出す（2026-11-13）。ユーザーに確認を求めるときは「マージ」「PR」と言わず、「この変更を本体に取り込んでよいか」と平易に聞き、何が変わるかを一言添える（ユーザー 2026-11-13「マージが僕には理解しづらい」）。
- 順番は企画書のロードマップのステップ A〜I。作品の顔になる場面と遊びの流れを、部屋や小物の磨きより先にする。プレイヤーから見えない所の崩れには時間を使わない。
- 画：刷りの網点の細かさは変えない。夕方の刷りと光は今の標準のまま。家の夜は夜の刷り（look=1）。UI と文字は作品世界の中の物（台詞は証言の書き起こしの形、名前は話す人が変わったら出す）。
- 受け取れば楽になる物（画像生成、Tripo、Mixamo、参考写真）は Claude から頼む。指示は日本語で、1ブロックに1つ、そのまま貼れる形で /mnt/project-files/段階N/ に置く。スキャンはしばらくできない。
- 素材は、ライセンスを docs/素材とアドオン.md に書いてから使う。
- docs/決定事項.md にあることは聞き直さない。

**作業環境**
- GPU なし。CPU とメモリは会話ごとに違う（`nproc; free -g`）。prep は1本ずつ（同時だとメモリ不足）。
- 長い処理はファイルに書いた1本のスクリプトにして run_in_background で走らせ、ログの最後（`== DONE`、`_FAIL`、`CHECK_DONE`）で結果を見る。
- 確認画・ログ・書き出した版はリポジトリに入れない（$WORK、$BUILD）。パスは paths.env の1か所。

## 速い回し方（1往復）
1. 直す → `FAST=1 bash blender/build.sh <番号>`（焼き込みは使い回し。片方の場面だけの直しなら `SCENES=night` などで、その場面だけ書き出す）
2. `FAST=1 WHO=<直した人物> bash blender/check.sh <pck> <直す前の pck> <指摘の一覧>`（その人物と指摘の項目だけ）
3. 直りきったら、全項目の `bash blender/check.sh`（送る前。FAST なし）→ 一覧.md がすべて ○ → 送る
4. ユーザーの OK → `bash blender/build.sh <番号>`（配布用。中身が変わった所だけ焼き直す）
